**Add new pure function `panel_key_to_command`:**
```rust
/// Translate a key event into an `InputCommand` based on which panel has focus.
///
/// Returns `None` for unmapped keys. Does not handle Cli focus (caller manages
/// text input directly in UiState).
pub fn panel_key_to_command(
    key: KeyCodeSimple,
    focus: FocusPanel,
) -> Option<InputCommand> {
    match focus {
        FocusPanel::Sequencer => match key {
            KeyCodeSimple::Left  => Some(InputCommand::StepSelectDelta(-1)),
            KeyCodeSimple::Right => Some(InputCommand::StepSelectDelta(1)),
            KeyCodeSimple::Up    => Some(InputCommand::NoteDelta(1)),
            KeyCodeSimple::Down  => Some(InputCommand::NoteDelta(-1)),
            KeyCodeSimple::Space => Some(InputCommand::ToggleStep),
            KeyCodeSimple::Enter => Some(InputCommand::Confirm),
            _ => None,
        },
        FocusPanel::SeqParams | FocusPanel::RandParams => match key {
            KeyCodeSimple::Left  => Some(InputCommand::PanelParamSelect(/* handled in ui.rs */0)),
            KeyCodeSimple::Right => Some(InputCommand::PanelParamSelect(/* handled in ui.rs */0)),
            KeyCodeSimple::Up    => Some(InputCommand::PanelParamDelta(1)),
            KeyCodeSimple::Down  => Some(InputCommand::PanelParamDelta(-1)),
            _ => None,
        },
        FocusPanel::Cli => None, // Cli key handling is done in ui.rs directly
    }
}
```
Note: For SeqParams/RandParams left/right, `ui.rs` adjusts the local param
index and then sends `PanelParamSelect(new_idx)` — `panel_key_to_command` can
return a sentinel or this can be split. Follow whatever approach keeps the
function pure and testable.

Update or replace existing tests in the `tests` module to match the new
behavior. The old `overlay_key_arrows_still_work` test must be updated or
removed since `overlay_key_to_command` is gone.

## Description

Update `engine/src/main.rs` to wire the new `MidiCtrlMsg` dual-channel
architecture and remove the pre-TUI port/channel prompt calls. This is the
final integration step — it connects all the pieces built by the preceding
tasks.

Files to touch: `engine/src/main.rs`

**Remove:**
- Call(s) to `choose_midi_port(...)` (gated `#[cfg(feature = "hw-io")]`)
- Call(s) to `choose_midi_channel()` (gated `#[cfg(feature = "hw-io")]`)
- Any `state.write().midi_channel = selected_midi_channel` initialization using
  the removed prompt result
- Any `selected_midi_port` / `selected_midi_channel` local variables

**Add `MidiCtrlMsg` channel:**
```rust
use engine::midi_out::MidiCtrlMsg;

let (midi_ctrl_tx, midi_ctrl_rx) = std::sync::mpsc::sync_channel::<MidiCtrlMsg>(16);
```

Place this after the existing `cmd_tx`/`cmd_rx` channel creation and before
the thread spawns.

**Update `run_midi_out` call** to pass `midi_ctrl_rx`:
```rust
// Before (old):
thread::spawn(move || run_midi_out(midi_rx, port_name));

// After (new):
thread::spawn(move || run_midi_out(midi_rx, midi_ctrl_rx, port_name));
```

The `port_name` argument becomes `None` at startup (no pre-TUI prompt) — or
reads from a CLI argument / environment variable if the project already has
that pattern. Check `main.rs` to confirm the current pattern and preserve
any existing non-prompt port selection logic.

**Update `run_ui` call** to pass `midi_ctrl_tx`:
```rust
// Before (old):
thread::spawn(move || run_ui(state.clone(), cmd_tx.clone(), ui_notify_rx));

// After (new):
thread::spawn(move || run_ui(state.clone(), cmd_tx.clone(), ui_notify_rx, midi_ctrl_tx));
```

Do NOT change the thread shutdown order or any other thread spawn sites.
Do NOT change the clock thread, HID thread, or state-processor thread wiring.

**Smoke test criterion:** After this change, `cargo build -p engine --release`
must succeed and the binary must start without printing any pre-TUI prompts
to stdout when run without arguments.
